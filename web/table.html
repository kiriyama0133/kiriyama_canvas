模型写在这个页面的 <script> 里，不在 C++ 里。整页只有一件事要做： 把列定义 + 42 行数据挂到 window.KIRIYAMA_TABLE_MODEL 上。编码、跨语言调用、 时机全部由 entry.js（构建时用 --post-js 拼进 table.js）负责， 页面里看不到 ccall、看不到分隔符协议。运行时换数据只要 Module.loadTable(model)，也可以直接喂 JSON 文本。换数据 / 加列 / 改数字格式， 都不用重新编译。
组件本身不持有数据（const TableData* + 调用方给的 dataVersion）， 持有的是视图状态：排序键、选中行、滚动量。排序不重排数据，只重排 order[]（行下标置换），所以选中、行身份都不受影响——点表头把顺序倒过来， 选中的那一行仍然跟着行走，而不是跟着位置走。
交互：点可排序表头 → 升序 / 降序 / 恢复原序 三态循环，只有 sortable 的列会变手型； 滚轮滚动；点行选中；上下方向键、PageUp / PageDown、Home / End 移动选中并自动滚到可见。 点一下某个表头，数字列按 double 比较（不是按字符串），空值永远排在最后，不随升降序翻转。
列宽是量出来的：TableWidget::remeasure() 用字体度量取 max(表头, 各单元格)，再按可用宽度等比铺满。几何全在 core::computeTableLayout() 里算（列偏移 / 行矩形 / 可见范围 / 滚动夹紧）， 那部分是纯函数，有 21 项单元测试。
