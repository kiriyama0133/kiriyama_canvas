模型写在这个页面的 <script> 里，和表格同一套约定：把 { slices: [{ label, value }, …] } 挂到 window.KIRIYAMA_PIE_MODEL 上。编码、跨语言调用、时机全部由 entry.js（构建时用 --post-js 拼进 pie.js，和 table.js 共用一份胶水）负责。运行时换数据只要 Module.loadPie(model)。0 / 负数 / NaN 的片不画、不参与占比。
三层策略：scene::TooltipTarget（气泡内容与开关）→ scene::PieSlice（一个扇区：极坐标命中 + hover 外扩 + 默认气泡）→ scene::PieChart（数据指针 + core::computePieLayout + 每个可用扇区一个子节点）。命中是精确的半径 + 角度判定（覆盖 Widget::hitShape()），不是外接框——所以扇形之间的空隙点不到， 甜甜圈的内孔也点不到。
hover：扇区外半径沿径向平滑放大（角度边界不动，相邻扇区不露底、不闪白）， 气泡贴在扇区中径点上。默认气泡是 label · 数值 · 占比%；定制从低到高三个入口： setTooltipContent() 设静态内容、继承覆盖 tooltipContent() 按数据生成、TooltipHost::setResolver() 完全接管。
数据与样式都来自本页：slices 给数据、options 给外观 （字号 / 颜色 / 外扩 / 甜甜圈…，见上方 options 注释）。运行时 Module.loadPie({ slices, options }) 热替换，不用重新编译。
